# SO101 首轮 SmolVLA 训练方案

> 历史方案：本文形成于23–25号数据加入和正式训练之前，batch、数据总数和SSH状态均已变化。当前已完成10k，最新情况见 `../docs/交接文档.md`。不要据本文重启训练。

检查日期：2026-09-18。仅检查与规划，未启动训练、未改写原始数据。

## 已完成检查
- 11个数据集，共68个episode、39,814帧。
- 22个相机视频全部逐帧解码成功，每路视频帧数均与所属数据集的数据表行数一致。
- 各组features一致：两路640×480 RGB，标注30fps，六维动作及状态。
- 动作、状态未检出NaN或Inf。
- 抽查各组首帧：images.1为夹爪附近视角，images.3为外部视角；两天采集的光照、桌面布局有差异。
- 当前任务标签为数字编号，需要真实语言标注。视频可解码不等于每段任务成功，也不证明实际采样始终达到30Hz。
- SSH myserver 本次连接超时。此前A100 80GB配置尚需重新核验，尚未确认远端训练环境可直接使用。

## 数据准备
1. 确认全部episode的实际任务、相机是否换位、机械臂是否重新校准。
2. 按episode查看起始、抓取、抬升、释放、结束画面；剔除失败、人工协助、长时间无效停顿或明显异常片段。原始数据保留。
3. 若任务确实一致，在训练副本中统一标注 `Pick up the yellow cube and place it into the mesh container.`；不同任务分别准确标注。
4. 用安装版本的官方数据编辑工具合并并重建episode索引、视频偏移与统计量；不能直接拼接目录或只改info.json。
5. 固定两路相机语义映射，训练与部署必须相同，不能把相机编号或自动USB索引当作稳定语义。
6. 若68条全部合格，按完整episode划分约58条训练、10条验证，分配时兼顾采集批次与物体位置。不得随机按帧划分。不同校准体系的数据先核实动作定义再合并。

## 环境与模型
- 主线：预训练 `lerobot/smolvla_base` 微调；目标为本桌面黄方块抓取放置验证。
- 本地Windows负责采集与部署；Linux开发机负责训练。固定LeRobot版本及依赖，先确认当前驱动兼容性。
- 保留数据副本、源数据到新episode的映射、划分清单、配置、随机种子与模型checkpoint。
- ACT可在主线跑通后作为相同数据上的对照，不把ACT描述成语言条件VLA。

## 首轮参数（起点，非保证最优）
| 项目 | 设置 |
|---|---|
| 预训练模型 | lerobot/smolvla_base |
| 测试运行 | 100–200 steps，先跑通读取、前后向与保存加载 |
| 正式训练 | 先10,000 steps，再根据验证与实机结果决定是否到20,000 |
| batch size | 32起步；显存不足降16，有余量再评估64 |
| 学习率 | 1e-4起步，核对实际checkpoint与优化器配置 |
| 可训练部分 | 沿用SmolVLA适配设置，核对train_expert_only、train_state_proj、freeze_vision_encoder |
| num_workers | 4起步，按视频解码吞吐调整 |
| checkpoint | 每2,000 steps保存 |
| seed | 42 |
| 相机输入 | 两路RGB＋六维状态＋真实语言指令 |

验证损失需要单独接入保留episode的评估；不要把CLI环境评估频率当成离线数据验证。预训练模型的相机输入名称与数据字段要先核对并配置映射。

## 实机验证
1. 先离线加载checkpoint，检查动作维度、单位、归一化、相机顺序及预处理。
2. 修复现有串口无返回、相机超时问题后，再进行受限实机动作测试；训练本身不能解决通信故障。
3. 在笔记本上测推理延迟，再确定动作执行频率和动作分块，不能默认可稳定30Hz。
4. 选择未用于示教的5个起始位置，每个4次，共20次，记录成功率、耗时与失败类型。明确物体是否完全落入容器为成功条件。
5. 依据错误补录针对性示教。单一任务成功不能证明能理解任意语言或处理任意物体。
